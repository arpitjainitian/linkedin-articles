# 32. Can You Build an App by Describing It? | Vibe coding

![Cover](images/32-vibe-coding-cover.png)

*Explain It Like Hello World series: Vibe coding*

"Vibe coding." People build apps by chatting with an AI, without reading the code. Developers argue about it. Leaders wonder if it changes hiring.

## The hello world

Say to an AI tool: "Make me a page where my family can vote on dinner, with three options and a big result." A minute later, it works. You never looked at the code.

That's the hello world: **describe what you want, test the result, ask for changes**, and let the AI handle the code.

## One step further

AI coding tools write, run and fix code from plain-language requests. You steer by trying the app and saying "make the button bigger" or "it crashes when I click twice".

The term was coined by AI researcher Andrej Karpathy in early 2025. It's great for prototypes, personal tools and learning. For real products, someone still has to understand the code: security, data, costs and fixes don't vibe themselves.

## Where you've already met it

Non-programmers building small apps with AI app builders, and developers using AI agents to write most of a feature.

## The real name

**Vibe coding**.

- **Prompt:** the plain-language request you give the AI.
- **Prototype:** a quick working version to try an idea.
- **Technical debt:** shortcuts in code that cost you later.

## What it's not

Vibe coding isn't "no engineering needed". The easy 80% gets faster; the last 20% (security, scale, maintenance) still needs people who read the code.

## Take this to your next meeting

1. Use it to prototype ideas in hours, not weeks.
2. Have someone review anything that touches real users, money or data.
3. Keep the prototype and the production version as separate decisions.

Describe it, try it, fix it. Then have someone read the code.
