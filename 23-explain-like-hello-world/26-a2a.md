# 26. How Do AI Agents Talk to Each Other? | A2A (agent-to-agent)

![Cover](images/26-a2a-cover.png)

*Explain It Like Hello World series: A2A (agent-to-agent)*

"A2A." "Agent-to-agent protocol." As companies build many AI agents, they need a way for one agent to work with another, even from a different company.

## The hello world

Your travel agent needs a visa agent's help. First, they swap business cards: "I'm the visa agent, I can check requirements and book appointments, here's how to reach me." Then they hand over the task and get updates until it's done.

That's the hello world: **A2A** is a shared way for AI agents to introduce themselves, hand over tasks and report back.

## One step further

Each agent publishes a "card" describing what it can do and how to contact it. Another agent reads the card, sends a task, and gets progress updates and results in an agreed format, even if the two were built by different teams on different tools.

Google introduced the Agent2Agent protocol in 2025, and it's now developed as an open project. It complements MCP: MCP connects an agent to tools and data (Series 11); A2A connects agents to other agents.

## Where you've already met it

Early enterprise tools where, say, a hiring agent asks a separate background-check agent to do its part.

## The real name

**A2A**, the **Agent2Agent protocol**.

- **Agent card:** an agent's public description: what it does, how to reach it.
- **Protocol:** an agreed set of rules for talking.
- **Task hand-off:** one agent passing work to another.

## What it's not

A2A doesn't make agents trustworthy. Each agent still needs permissions and checks (Series 15 covers multi-agent pitfalls; Series 16 what agents are allowed to do).

## Take this to your next meeting

1. Ask whether your agents need to talk to other teams' agents at all.
2. Treat another agent's output like any outside input: check it.
3. Know the difference: MCP for tools, A2A for agents.
