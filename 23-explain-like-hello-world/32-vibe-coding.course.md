# Lesson 23.32: Vibe coding (course companion)

*Explain It Like Hello World. Not for LinkedIn.*

## Learning objective

After this lesson, you can explain vibe coding with a hello-world example, say how it really works in one step, and name its most common misunderstanding.

## The hello world, to retell

Say to an AI tool: "Make me a page where my family can vote on dinner, with three options and a big result." A minute later, it works. You never looked at the code.

## One step further

AI coding tools write, run and fix code from plain-language requests. You steer by trying the app and saying "make the button bigger" or "it crashes when I click twice".

The term was coined by AI researcher Andrej Karpathy in early 2025. It's great for prototypes, personal tools and learning. For real products, someone still has to understand the code: security, data, costs and fixes don't vibe themselves.

## Exercise

Explain vibe coding to someone non-technical in under one minute, using your own everyday example (not the one from the article). Then name one product where they have already met it.

## Quiz

1. What is the hello-world example for vibe coding? *Describe it, test it, ask for changes. That's vibe coding.*
2. What is it not? *Vibe coding isn't "no engineering needed". The easy 80% gets faster; the last 20% (security, scale, maintenance) still needs people who read the code.*
3. Name one place you've already met it. *Non-programmers building small apps with AI app builders, and developers using AI agents to write most of a feature.*

## Glossary

- **Prompt:** the plain-language request you give the AI.
- **Prototype:** a quick working version to try an idea.
- **Technical debt:** shortcuts in code that cost you later.
